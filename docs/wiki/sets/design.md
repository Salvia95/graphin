# 디자인

화면을 만들거나 고칠 때 읽는다. 색·간격·타입은 근거 없이 흔들리기 가장 쉬운 것들이고,
근거가 코드 옆에만 있으면 다음 사람이 그걸 못 읽는다.

**먼저 §0을 읽는다.** 본문은 Binance에서 추출한 참조 명세를 그대로 실은 것이라,
graphin에서 그대로 적용되지 않는 항목이 있다. 무엇이 갈리는지는 §0에만 적혀 있다.

## 먼저: graphin에 적용할 때 갈리는 것

- [토큰이 실제로 사는 곳](../../design-system.md#01-토큰이-실제로-사는-곳) —
  참조의 `{colors.x}` 표기가 가리키는 YAML은 없다. 구현은 Tailwind v4 `@theme`이고
  토큰 이름이 그대로 CSS 변수와 유틸리티 이름이 된다. **문서가 이름을 정하고 CSS가
  값을 정한다.**
- [폰트는 대체를 쓴다](../../design-system.md#02-폰트--대체를-쓴다) —
  BinanceNova·Plex는 라이선스 폰트라 못 쓴다. Inter와 Plex Mono 계열로 가되
  **웹폰트를 받아오지 않는다**: 로컬 도구가 외부 호스트에 요청을 걸 이유가 없다.
  숫자의 기능(자릿수 정렬)은 `tabular-nums`로 지킨다.
- [거래 토큰의 재범위](../../design-system.md#04-거래-토큰의-재범위--이-문서의-유일한-의도적-이탈) —
  참조는 초록·빨강을 가격 방향 전용으로 못 박지만 **graphin에는 가격이 없다.**
  같은 색값을 `status-good` / `status-alert`로 재범위한다. 이것이 유일한 의도적
  이탈이고, 다른 토큰을 같은 논리로 재해석하려면 근거를 거기 추가해야 한다.
- [노랑을 심각도에 쓰지 않는다](../../design-system.md#05-노랑의-희소성--심각도에-쓰지-않는다) —
  노랑의 힘은 희소성이다. 주 액션·워드마크·큰 통계 숫자에만 쓰고, 결정 큐의 네
  단계는 alert / watch / info / neutral로 따로 간다.
- [화면의 언어는 영어다](../../design-system.md#07-화면의-언어는-영어다) —
  UI 문자열과 Go가 만드는 결정 카피까지 전부 영어다. 한글은 문서·커밋 메시지와
  **화면에 지나가는 데이터**에만 남는다. 이유는 번역 품질이 아니라 어휘 분열이다 —
  drift·pin·trust 같은 용어를 화면에서만 옮기면 같은 개념이 두 이름을 갖는다.
- [다크 단일 모드](../../design-system.md#03-다크-단일-모드) —
  참조는 마케팅 다크·거래 라이트로 나누지만 콘솔은 대시보드 하나다. **라이트 모드를
  만들지 않는다** — 어중간하게 둘 다 지원하면 두 벌 다 덜 다듬어진다.

## 색과 타입

- [Colors](../../design-system.md#colors) —
  캔버스 #0b0e11 · 카드 #1e2329 · 한 단계 위 #2b3139. 경계선은 잉크가 아니라
  **표면의 계단**이라 hairline이 elevated와 같은 값이다. 브랜드 색은 노랑 하나뿐이고
  두 번째 브랜드 색을 들이지 않는다.
- [Typography](../../design-system.md#typography) —
  편집용과 숫자용을 나눈 것은 장식이 아니라 기능이다. 통계·카운트·비율은 전부 숫자
  스택으로 간다. display는 700 — 400으로 낮추면 트레이딩 플랫폼이 아니라 포트폴리오로
  읽힌다.

## 형태·간격·깊이

- [Shapes](../../design-system.md#shapes) —
  반경은 6~12px에 몰려 있다. pill은 "이것이 그 액션이다"를 뜻하는 예외라 아껴 쓴다.
- [Layout](../../design-system.md#layout) —
  4의 배수. 밴드 간격은 80px이고, 여백보다 **대비**가 분리를 맡는다.
- [Elevation & Depth](../../design-system.md#elevation--depth) —
  **평평한 표면 + 색 블록 분리.** 그림자·글래스모피즘·분위기 그라디언트를 쓰지 않는다.
  깊이는 캔버스와 카드의 명도 차가 만든다.

## 어기면 안 되는 것

- [Do's and Don'ts](../../design-system.md#dos-and-donts) —
  노랑을 본문이나 큰 면에 쓰지 않는다. 캔버스에 분위기 그라디언트를 얹지 않는다.
  주 버튼의 검정 글자를 흰색으로 뒤집지 않는다. display 굵기를 낮추지 않는다.
