# 콘솔 (P7)

콘솔을 이어받을 때 읽는다. **2026-08-22에 착수했다** — 그 전까지는 보류 결정이었고,
무엇이 그 판단을 뒤집었는지가 지금 범위를 정한다. 그래서 첫 항목들이 여전히
원래 근거와 재검토 조건이다: 조건 하나만 참이 됐으므로 **나머지를 근거로 범위를
넓히면 그때 다시 확인해야 한다.**

## 먼저: 지을지 말지

- [왜 안 지었나](../../console-spec.md#1-왜-안-지었나) —
  보류 시점의 기록이고 대가 계산은 아직 유효하다: 프런트엔드 툴체인은 Go 저장소에
  **영구히** 들어온다. 1차 범위가 이미 커맨드로 나온다는 ①도 여전히 참이다 —
  바뀐 것은 저울의 반대편이지 이쪽이 아니다.
- [다시 볼 조건](../../console-spec.md#2-다시-볼-조건) —
  **두 번째 조건이 참이 되어 판단이 뒤집혔다.** knowledge set 승인은 사람의 개입이
  구조적으로 필수인데 그 마찰이 위키가 자라는 것을 막는다. 여러 워크스페이스와
  시계열은 **여전히 거짓이고 범위를 넓히는 근거가 될 수 없다.**
- [열린 질문](../../console-spec.md#8-열린-질문) —
  쓰기는 넣되 **경계는 워킹 트리다**: 커밋하지 않으므로 "리뷰가 git diff"라는
  성질이 산다. `wiki queue` 확장은 배제됐다 — 그건 읽는 마찰만 줄인다. 인증 없는
  localhost가 devcontainer에서도 괜찮은가만 아직 열려 있다.

## 짓는다면 즉시 걸리는 것

- [콘솔은 인덱스를 열 수 없다](../../console-spec.md#3-먼저-알아야-할-제약--콘솔은-인덱스를-열-수-없다) —
  `graph.Open`이 델타 로그를 truncate하므로 별도 프로세스는 인덱스를 못 연다.
  1차 범위 셋 중 **둘은 인덱스 무관이고 게이지 하나만 걸린다** — 그걸 범위에서
  빼면 위험이 통째로 사라진다.
- [API는 커맨드와 같은 함수의 얇은 껍질](../../console-spec.md#5-규율--api는-커맨드와-같은-함수의-얇은-껍질) —
  분리는 끝났다(`internal/wiki/queue.go`). 남는 규칙 둘: **절단은 렌더러에 있고**
  JSON은 전량을 낸다, **빈 배열은 `null`이 아니라 `[]`다**. 후자는 취향이 아니라
  빈 큐가 정상 상태이기 때문이다.
- [첫 조각](../../console-spec.md#9-짓기로-했다면--첫-조각) —
  6단계 중 1~4 완료. 승인은 `status`가 아니라 `reviewed`에 `human:<id>`를 남기고,
  폼은 산문만 바꾸며 **`evidence`는 못 바꾼다**(입회 규칙이 타이핑으로 충족되면 안 된다).
  **다음은 5단계(Vite + `go:embed`)이고 거기서 처음으로 되돌리기 어려워진다.**

## 배포에 붙는 대가

- [빌드·릴리스에 붙는 것](../../console-spec.md#6-빌드릴리스에-붙는-것) —
  릴리스 build 잡이 `debian:bullseye` 컨테이너 안에서 도므로 node가 거기 들어가야
  하고, glibc 하한에 영향이 없는지 확인해야 한다. `dist/`를 커밋할지 CI에서
  빌드할지도 결정 사항이다 — 안 커밋하면 `go build`만으로는 안 빌드된다.
- [스택](../../console-spec.md#4-스택-설계-확정분-뒤집으려면-근거가-필요) —
  React+TS+Vite+Tailwind+shadcn, `go:embed`. 기각된 셋과 사유(htmx는 생성 품질,
  SvelteKit은 학습 분포, Next.js는 런타임 Node)가 함께 있다.
- [버저닝](../../console-spec.md#7-버저닝) —
  새 서브커맨드는 §13.2의 다섯을 깨지 않으므로 **patch**이고 릴리스 노트
  프렐류드도 불필요하다.
