# 콘솔 (P7)

콘솔을 이어받을 때 읽는다. **2026-08-22에 착수했다** — 그 전까지는 보류 결정이었고,
무엇이 그 판단을 뒤집었는지가 지금 범위를 정한다. 그래서 첫 항목들이 여전히
원래 근거와 재검토 조건이다: 조건 하나만 참이 됐으므로 **나머지를 근거로 범위를
넓히면 그때 다시 확인해야 한다.**

## 먼저: 지을지 말지

- [왜 안 지었나](../../console-spec.md#1-왜-안-지었나) —
  보류 시점의 기록이고 대가 계산은 아직 유효하다: 프런트엔드 툴체인은 Go 저장소에
  **영구히** 들어온다. 1차 범위가 이미 커맨드로 나온다는 ①도 여전히 참이다 —
  바뀐 것은 저울의 반대편이지 이쪽이 아니다.
- [다시 볼 조건](../../console-spec.md#2-다시-볼-조건) —
  **조건 셋 중 둘이 참이 됐다.** ②승인 마찰이 짓게 만들었고, ③시계열은 화면이
  이미 채택률을 인용하면서 참이 됐다 — 인용은 하면서 분모를 못 보여 주는 화면이
  `usage-spec.md` §4.2.1의 고장을 재현하기 때문이다(세션 채택 57% vs 헤드라인
  15%). **①여러 워크스페이스 롤업만 여전히 거짓이고 범위를 넓히는 근거가 아니다.**
- [열린 질문](../../console-spec.md#8-열린-질문) —
  쓰기는 넣되 **경계는 워킹 트리다**: 커밋하지 않으므로 "리뷰가 git diff"라는
  성질이 산다. `wiki queue` 확장은 배제됐다 — 그건 읽는 마찰만 줄인다. **남은 둘**:
  인증 없는 localhost가 devcontainer에서도 괜찮은가(그 근거가 프로세스 실행까지는
  안 늘어난다고 판정한 선례가 §14에 있다), 그리고 프런트엔드 테스트 러너를 들일
  것인가.

## 짓는다면 즉시 걸리는 것

- [콘솔은 인덱스를 열 수 없다](../../console-spec.md#3-먼저-알아야-할-제약--콘솔은-인덱스를-열-수-없다) —
  `graph.Open`이 델타 로그를 truncate하므로 별도 프로세스는 인덱스를 못 연다.
  1차 범위 셋 중 **둘은 인덱스 무관이고 게이지 하나만 걸린다** — 그걸 범위에서
  빼면 위험이 통째로 사라진다.
- [API는 커맨드와 같은 함수의 얇은 껍질](../../console-spec.md#5-규율--api는-커맨드와-같은-함수의-얇은-껍질) —
  분리는 끝났다(`internal/wiki/queue.go`). 남는 규칙 둘: **절단은 렌더러에 있고**
  JSON은 전량을 낸다, **빈 배열은 `null`이 아니라 `[]`다**. 후자는 취향이 아니라
  빈 큐가 정상 상태이기 때문이다.
- [첫 조각](../../console-spec.md#9-짓기로-했다면--첫-조각) —
  1~5·7·8 완료 — 콘솔이 동작하고 디자인과 자동 갱신까지 들어갔다. 승인은 `status`가
  아니라 `reviewed`에 `human:<id>`를 남기고, 폼은 산문만 바꾸며 **`evidence`는 못
  바꾼다**(입회 규칙이 타이핑으로 충족되면 안 된다). 6은 게이지를 범위 밖에 두는
  결정이라 할 일이 아니다.
- [갱신은 감시가 아니라 폴링이다](../../console-spec.md#10-갱신--화면이-자기가-시킨-일의-결과를-본다) —
  카드가 시키는 일은 전부 에디터에서 일어나므로 화면이 스스로 다시 읽어야 한다.
  `internal/watch`를 **안 쓴다** — 재귀 OS 워치가 `node_modules` 있는 트리에서
  머신의 inotify 한도를 태우고 MCP 서버의 워처까지 죽인다. SSE는 "움직였다"만
  싣고 페이로드는 안 싣는다(§5).
- [결정은 끝날 수 있어야 한다](../../console-spec.md#11-결정이-끝날-수-있어야-한다-2026-08-23) —
  `uncovered`만 사람이 끝낼 수 없는 종류였다. 이제 miss마다 **기록될 때와 같은
  술어**(`Select(role, task).Empty()`)를 다시 묻는다. role 푸시가 무조건이라 넓은
  세트 하나가 그 role의 miss를 전부 물리는 긴장이 남아 있고, 고치는 대신
  `Health.Answered`로 **보이게** 했다.
- [repin의 범위](../../console-spec.md#12-repin의-범위-2026-08-23) —
  드리프트 카드는 절 하나를 확인하라고 하는데 `RepinAll`은 안 읽은 엔트리까지
  축복한다. `RepinEntry`가 하나만 갱신하고, 반쪽 쌍은 400·없는 엔트리는 404다.
  `Repin all`은 그룹 헤더로 갔다.
- [밀어내기 두 개](../../console-spec.md#13-밀어내기-두-개--지시만-있고-버튼이-없던-것-2026-08-23) —
  용어 회수는 **지운다**(`deprecated`는 계속 서빙되므로 슬롯을 안 비우고, 보관
  디렉터리는 아무도 안 치우는 무덤이다). 세트 편집은 **수술이지 재렌더가 아니다** —
  저자의 리스트 표기까지 보존한다. 세트 삭제는 일부러 안 넣었다.
- [Open은 링크지 엔드포인트가 아니다](../../console-spec.md#14-open-링크--왜-엔드포인트가-아니라-링크인가-2026-08-23) —
  인증 생략의 근거(루프백)는 워킹 트리 쓰기까지는 늘어나도 **임의 프로그램 실행까지는
  안 늘어난다.** 검증한 스킴만 싣고 나머지는 `--editor` 템플릿으로 받는다 —
  아무 일도 안 하는 링크는 링크가 없는 것보다 나쁘다.

## 배포에 붙는 대가

- [빌드·릴리스에 붙는 것](../../console-spec.md#6-빌드릴리스에-붙는-것) —
  전부 정해졌다. **릴리스 컨테이너에 node를 넣지 않는다**(별도 잡 + 아티팩트)라
  glibc 하한 확인이 필요 없어졌고, **`dist/`는 커밋하지 않되 `.gitkeep`으로
  `go build` 단독 빌드를 지킨다.** `make ui`는 `build`의 선행 조건이 아니다.
- [스택](../../console-spec.md#4-스택-설계-확정분-뒤집으려면-근거가-필요) —
  React+TS+Vite+Tailwind+shadcn, `go:embed`. 기각된 셋과 사유(htmx는 생성 품질,
  SvelteKit은 학습 분포, Next.js는 런타임 Node)가 함께 있다.
- [버저닝](../../console-spec.md#7-버저닝) —
  새 서브커맨드는 §13.2의 다섯을 깨지 않으므로 **patch**이고 릴리스 노트
  프렐류드도 불필요하다.
