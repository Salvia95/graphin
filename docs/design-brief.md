# 디자인 요청서 — graphin console

Claude Design에 넘기는 문서다. 무엇을 만드는 화면인지, 무엇이 이미 정해졌는지,
그리고 **무엇이 물리적으로 불가능한지**를 적는다. 마지막이 이 문서의 존재 이유다 —
시안이 되돌아오는 가장 흔한 이유가 제약을 모르고 그린 것이기 때문이다.

시각 언어의 현재 상태와 그 근거는 `docs/design-system.md`에 있다. 이 요청서는 그것을
**대체하는 것이 아니라 갱신을 요청하는 것**이다.

## 1. 이게 무슨 화면인가

`graphin console`은 개발자가 자기 저장소에서 띄우는 **로컬 웹 콘솔**이다.

```
graphin console --root <repo>     →  http://127.0.0.1:7673
```

graphin은 코드베이스를 그래프로 색인해 에이전트가 탐색하게 하는 도구이고, 그 위에
**위키**라는 지식 계층이 있다. 위키는 사람의 개입이 구조적으로 필수다 — 에이전트가
용어 후보를 제안할 수는 있지만 **발행은 절대 못 하고**, 사람이 승인해야 한다.

이 콘솔은 그 개입을 받는 자리다. 터미널에서 텍스트로 처리하기에 부담이 커서 만들었다.

**사용자는 한 명이다.** 그 저장소를 소유한 개발자. 다중 사용자·권한·인증이 없다.

## 2. 화면의 구조 (현재)

한 페이지, 탭 둘.

```
┌─ header ────────────────────────────────────────────┐
│  graphin console            [Decisions 9] [Wiki map] │
├─ tiles ─────────────────────────────────────────────┤
│  Wiki health │ Decisions │ Glossary │ Adoption      │
├─ tab: Decisions ────────────────────────────────────┤
│  [All 9] [Broken link 1] [Drift 2] [Awaiting 1] …   │  ← 필터 칩
│  ┌───────────────────────────────────────────────┐  │
│  │▌Broken link · ops                             │  │  ← 왼쪽 색 띠 = 심각도
│  │ docs/handbook.md#롤백-절차                     │  │
│  │ The target is gone — a heading was renamed…   │  │
│  │ Next · Fix the link in the set file (ops:8)   │  │
│  └───────────────────────────────────────────────┘  │
│  … 심각도 순으로 계속                                │
└─────────────────────────────────────────────────────┘
```

**결정 큐가 본체다.** 사용자가 이 화면에 오는 이유는 "지금 무엇을 해야 하나" 하나이고,
나머지는 전부 그 질문의 맥락이다.

`Wiki map` 탭에는 세트 목록(엔트리 수·제시 대비 열람·문제 배지)과 용어 표(신뢰 등급·
상태·인용 수·별칭)가 있다.

## 3. 하드 제약 — 어길 수 없는 것

### 3.1 외부 요청이 하나도 불가능하다

페이지는 **Go 바이너리에 `go:embed`로 박혀** 루프백에서 서빙된다. 오프라인에서 동작해야
한다.

- **웹폰트 CDN 금지** (Google Fonts 포함)
- 원격 이미지·아이콘·스크립트·분석 도구 **전부 금지**
- 모든 자산은 빌드 산출물 안에 있거나 인라인이어야 한다

### 3.2 폰트 — 자체 호스팅은 되지만 한글은 폴백이다

이게 가장 자주 오해되는 지점이라 정확히 적는다.

| | 가능한가 | 비용 |
|---|---|---|
| 원격 폰트 로드 | **불가** | — |
| Latin woff2 자체 호스팅 | **가능** | 60KB ≈ 21.3MB 바이너리의 **0.27%** |
| 한글 커버리지 자체 호스팅 | 사실상 불가 | 서브셋해도 수백 KB~MB |

**화면에 지나가는 데이터에는 한글이 섞인다.** UI 문자열은 전부 영어지만(§3.5), 결정
카드의 제목은 사용자가 쓴 작업 문구라서 `프로덕션 DB 마이그레이션을 무중단으로 돌린다`
같은 것이 그대로 뜬다.

즉 **어떤 폰트를 고르든 한글은 시스템 폴백으로 렌더된다.** 디자인은 Latin 커스텀 폰트와
시스템 한글 폰트가 **같은 카드 안에서 섞인 상태**에서 성립해야 한다. 시안을 만들 때
한글 문자열을 반드시 포함해 주기 바란다 — Latin만으로 그린 시안은 실물과 다르다.

숫자는 별도 스택으로 간다(자릿수 정렬 목적). 지금은 `tabular-nums`를 건 모노스페이스다.

### 3.3 다크 단일 모드

라이트 모드를 만들지 않는다. 대시보드 하나이고, 어중간하게 둘 다 지원하면 두 벌 다
덜 다듬어진다.

### 3.4 데스크톱 전용

로컬 개발 도구다. **1280px 이상만 대상**으로 하고 모바일 대응에 시간을 쓰지 않아도 된다.

### 3.5 UI 문자열은 영어, 데이터는 원문

`drift` `dangling` `pin` `set` `trust` `canonical` 같은 용어는 코드와 문서에서 영어로
확정돼 있다. 화면에서만 번역하면 같은 개념이 두 이름을 갖는다.

### 3.6 일러스트·사진이 없다

쓸 수 있는 이미지 자산이 없고, 만들면 embed에 들어간다. 아이콘이 필요하면 **인라인
SVG**로 최소한만 쓰는 것을 전제한다.

## 4. 데이터 — 시안이 허구가 되지 않도록

### 4.1 결정 8종과 심각도

정렬 순서는 결과가 아니라 **주장**이다. 끊어진 링크는 지금 독자에게 손해를 입히고,
안 읽히는 세트는 토큰을 물리고, 답 없던 작업은 다시 부딪히기 전까지 아무 비용도 아니다.

| # | kind | 뜻 | 현재 톤 |
|---|---|---|---|
| 0 | `dangling` | 세트가 가리키는 절이 사라짐 (헤딩 리네임/파일 이동) | alert |
| 1 | `glossary_full` | 용어집 상한(30) 도달 — 승인이 막힘 | alert |
| 2 | `expired` | 세트/용어가 자기 `stale_after`를 지남 | watch |
| 3 | `drift` | 핀은 살아 있지만 본문이 바뀜 — 요약이 안 맞을 수 있음 | watch |
| 4 | `approve` | 용어 후보가 사람을 기다림 (**유일하게 폼이 붙는 카드**) | info |
| 5 | `stale_skill` | 생성된 role 스킬이 근거와 불일치 | watch |
| 6 | `unread_set` | 3회 이상 제시됐고 0회 열림 | neutral |
| 7 | `uncovered` | 위키가 답 못 한 작업 (같은 문구는 접어서 횟수로) | neutral |

### 4.2 한 결정이 들고 있는 것

```json
{
  "kind": "drift", "severity": 3,
  "title": "docs/handbook.md#배포-절차",
  "detail": "The section changed since it was registered…",
  "action": "Re-read it, confirm the summary still holds, then repin",
  "set": "ops", "node_id": "…", "canonical": "…",
  "count": 2, "evidence": ["pkg.editor.Post", "pkg.feed.Renderer"], "role": "backend"
}
```

`title`은 노드 ID(경로+앵커)이거나 용어 이름이거나 **사용자가 쓴 문장**이다. 길이가
크게 흔들리고 줄바꿈이 필요하다.

### 4.3 실제 분포 — 두 극단을 다 그려야 한다

| | 건강한 저장소 (실측) | 문제 있는 저장소 (실측) |
|---|---|---|
| 결정 | **2건** (uncovered만) | 9건, 8종 중 8종 |
| 세트 | 4 | 2 |
| 용어 | **0** | 1 |
| 끊어짐/드리프트 | 0 / 0 | 1 / 2 |

**빈 상태가 정상 상태다.** 위키가 건강하면 결정 큐가 짧고 용어집이 비어 있다. 지금
디자인은 그때 화면이 허전해 보이는 문제가 있다 — 이건 데이터가 없는 게 아니라 **좋은
소식**인데 그렇게 안 읽힌다.

반대쪽 상한도 있다. `uncovered`는 답 못 한 작업마다 하나씩 쌓이므로 **수십~수백 건**이
될 수 있다. 스크롤·그룹핑·접기 전략이 필요하다.

### 4.4 다른 데이터

- 타일: `Wiki health`(끊어짐/드리프트/만료) · `Decisions`(총계) · `Glossary`(n/30) ·
  `Adoption`(graphin 쓴 세션/전체 세션, 이벤트 수)
- 세트: 이름·제목·요약·엔트리 수·**제시 대비 열람**·mode(live/pinned)·role·선행 세트
- 용어: canonical·**신뢰 등급**(`human-reviewed` / `machine-confirmed` / `unverified`)·
  상태·인용 수·별칭. 신뢰는 선언이 아니라 **누가 리뷰했는지에서 파생**된다

## 5. 이미 정해진 것 — 다시 논의하지 않아도 되는 것

`docs/design-system.md`가 근거를 갖고 있다. 뒤집으려면 근거가 필요하지만, 기본은 유지다.

- **평평한 표면 + 색 블록 분리.** 그림자·글래스모피즘·분위기 그라디언트 없음. 깊이는
  캔버스(#0b0e11)와 카드(#1e2329)의 명도 차가 만든다
- **브랜드 색은 하나.** 노랑 #FCD535 — 주 액션·워드마크·통계 숫자에만. 희소성이 힘이다
- **노랑을 심각도에 쓰지 않는다.** 그래서 심각도는 alert/watch/info/neutral로 따로 간다
- 반경 6~12px, 간격은 4의 배수
- 검정 글자 위 노랑 버튼은 뒤집지 않는다

## 6. 열려 있는 것 — 요청하는 것

### 6.1 주 요청: 결정 큐를 한눈에 읽히게

지금은 카드가 세로로 쌓이고 왼쪽 4px 색 띠가 심각도를 나른다. **8종을 훑어서 구분하기에
충분한가**가 의문이다. 밀도·그룹핑·타이포 위계를 다시 봐 주기 바란다.

### 6.2 색각 이상 대응 (알려진 약점)

지금 alert(#f6465d 빨강)와 watch(#f0b90b 호박)가 인접한 심각도인데, **적록 색각 이상에서
이 둘이 가장 헷갈리는 조합**이다. 색만으로 심각도를 나르지 않는 방법이 필요하다 —
형태·위치·라벨 중 무엇으로 보강할지.

### 6.3 빈 상태를 "좋은 소식"으로

§4.3의 문제다. 결정 0건은 결함이 아니라 위키가 건강하다는 뜻인데 지금은 빈 화면으로
읽힌다.

### 6.4 승인 폼

8종 중 유일하게 인터랙션이 붙는 카드다. 지금은 카드 안에서 펼쳐지는 인라인 폼인데,
목록 흐름을 깨지 않으면서 편집에 집중시키는 방법이 있는지.

### 6.5 두 탭의 관계

`Decisions`와 `Wiki map`이 지금은 대등한 탭인데, 실제 비중은 대등하지 않다. 지도를
사이드 레일이나 하위 뷰로 내리는 게 맞을 수도 있다.

## 7. 결과물로 받고 싶은 것

1. 위 구조의 시안 — **최소 두 상태**: 건강한 저장소(결정 2건, 용어 0개)와 문제 있는
   저장소(결정 9건 이상, 8종 혼재)
2. 토큰 갱신안 — 색·타입·간격. 현재 값은 `internal/console/ui/src/index.css`의
   Tailwind v4 `@theme` 블록에 있고, 이름이 그대로 유틸리티 이름이 된다
3. 심각도를 색 외의 축으로도 나르는 방법 (§6.2)

**시안에 한글 문자열을 반드시 포함해 주기 바란다** (§3.2). Latin만으로 그린 것은 실물과
다르다.

## 8. 지금 상태를 직접 보려면

```
make build
./bin/graphin console --root .          # 건강한 저장소
```

문제 있는 저장소의 화면은 위키에 끊어진 링크·드리프트·승인 대기가 있어야 재현된다.

**관련 문서**: `docs/design-system.md`(시각 언어와 그 근거) ·
`docs/console-spec.md`(콘솔이 왜 존재하고 무엇을 쓰지 않는지)
