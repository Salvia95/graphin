## 바뀐 규칙 (둘, 전부 `grade()` 안)

1. **말줄임 경로는 인용이 아니다.** `PATH_RE`에 걸린 경로에 `...` 또는 `…`이 들어 있으면
   `fake_citations`에서 빼고 `elided_citations`로 따로 센다. `docs/eval/.../scores.json`은
   에이전트가 본 디렉터리를 줄여 쓴 것이고 "이 경로가 있다"는 주장이 아니다.
2. **금지 리터럴 앞 같은 줄 60자 안에 부정어가 있으면 부정 문맥이다.** 기존 문장 규칙
   (`[.\n]`으로 자른 조각 안에 부정어가 없으면 히트)은 그대로 두고, 그 위에 예외 하나를
   더했다. 문장 규칙은 `e.g.`·`go.mod`의 점에서 문장을 잘라 "no Redis client library
   (e.g. `go-redis`)"의 리터럴을 부정어 없는 조각에 고립시켰다. **창은 줄바꿈을 넘지
   않는다** — 인수인계 §7-1의 "60자"보다 좁게 구현했다. 목록 항목·문단은 진짜 경계이고,
   이 판정이 피해야 할 고장 방향은 여전히 "두 문장 위의 부정어로 날조가 통과하는 것"이다.

바꾸지 않은 것: 문장 규칙 자체(점을 포함한 금지 리터럴 `redis.Client`·`graphin.proto`·
`grpc.NewServer`는 조각 안에 통째로 들어갈 수 없어 **원래부터 절대 발화하지 않는다** —
findings §4에 적었다), 판정 축·게이트·러너.
