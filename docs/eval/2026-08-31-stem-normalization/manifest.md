# 런 스냅샷 매니페스트 — 2026-08-31 어간 정규화

BM25 인덱스가 텀을 정규화하기 시작한 변경(`internal/lexical/stem.go`)이
SWE-Explore 지표를 어느 쪽으로 움직이는지 확인한 런. 색인과 질의 양쪽에
대칭으로 걸리는 개입이므로 **가설 검증이 아니라 회귀 확인 + 개선 판정**이고,
같은 벤치·같은 config에서 기준선과 페어 비교만 한다.

## 재현 좌표

- graphin 신규: 작업 트리 = `e792c00` + `internal/lexical` 어간 정규화.
  변경 내용은 `Index.Upsert`/`Index.Search`가 텀을 `Stem`으로 접는 것 —
  영어는 복수형·`-ing`/`-ed`·어말 `e`, 한국어는 어말 조사 1개. 1:1 사상이라
  문서 길이는 그대로다. 스냅샷 버전 1→2(기존 인덱스는 한 번 재색인).
- graphin 기준선: **같은 날 새로 빌드했다.** `git archive e792c00`로 커밋된
  트리를 꺼내 `go build`. 디스크의 `out/sweep-451`(2026-07-25 빌드)을 재사용하지
  **않았다** — 그 사이 Tier-0 변경 등으로 코드가 여러 번 움직였고, 그것을
  기준선으로 쓰면 이 변경 하나가 아니라 그동안의 전부를 재게 된다.
- 데이터셋: `bench.enriched.jsonl` (sha256 `a1e5dd8873b01c15…`) — 2026-07-25 /
  08-08 런과 **동일 파일**. 451 verified 인스턴스 전부.
- 스코어러: SWE-Explore-Bench 공식 `eval.py` @ `3c12dc5`. 채점은 항상 이것.
- 모델: 없음. **lexical-only** 런이다(`--semantic` 미지정) — 변경의 사정거리가
  BM25 텀 정규화라 벡터를 끌어들이면 비교가 흐려진다.

## 설계

- 27점 스윕(top_k {5,10,20} × rrf_k {20,60,100} × min_conf {0.75,0.85,0.95}),
  451 인스턴스, `--sweep`. 기준선 **1h3m35s**, 신규 **1h3m33s**, 둘 다
  caveat·태스크 에러 0.
- **lexical-only에서 `rrf_k`는 제출을 바꾸지 않는다** — 융합할 두 번째 랭킹이
  없기 때문이고, 세 값의 제출 파일이 md5까지 동일한 것으로 확인했다. 즉 27
  config 중 서로 다른 것은 **9개**이며, 유의 셀을 셀 때 3배 복제를 빼고 읽어야
  한다.
- grep 베이스라인은 재실행하지 않았다. 이 변경이 grep 정책을 건드리지 않으므로
  `out/grep-451`이 그대로 유효하다.
- 판정 단위는 집계 평균이 아니라 **인스턴스 단위 페어 비교**(`stem_detail.md`).
  같은 벤치·같은 결정론 정책이라 451개가 정확히 짝지어진다.
- per-repo 층화를 함께 낸다. django가 표본의 46%(209/451)라 집계 하나로는
  "django가 끌었나"에 답할 수 없다.
