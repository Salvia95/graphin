# 검증 결과 해석 (2026-07-23, Verified 서브셋 40개, lexical-only)

`report.md`의 수치에 대한 해석과 후속 조치 제안. 채점은 전부 SWE-Explore-Bench
공식 `eval.py`가 수행했다.

## 확정된 판정

- **H3 PASS (강함)**: 같은 300라인 예산에서 graphin recall 0.107 vs
  grep -C20 0.026 (**4.1×**), ndcg@300 0.348 vs 0.101, 제출 라인은 grep의
  **3.1%** (1,809 vs 57,646). "grep의 3% 분량으로 4배 리콜"은 README에 실을
  수 있는 반증 가능한 문장이다. 단 무예산 recall은 grep이 높다(0.687 vs
  0.213~0.309) — grep은 32배 분량을 쏟아부어 얻는 수치라는 맥락 필수.
- **H2 PASS — 단, 공허하게 참(vacuous)**: Δ가 전 구간 정확히 0.00인 이유는
  min_confidence 스윕(0/0.5/0.8)이 **아무 엣지도 거르지 않기 때문**이다.
  graphin의 confidence 최저 티어가 0.8이므로 0.8 미만의 floor는 no-op이다.
  기본값 0.5는 안전하지만, 이 파라미터가 의미를 가지려면 floor > 0.8
  구간(예: 0.85/0.95)을 스윕해야 한다.

## 스윕에서 나온 실질 발견

- **top_k가 유일하게 움직이는 손잡이**: 5→10에서 recall +5.7%p(0.213→0.270),
  recall@300 +1.6%p(0.107→0.123). 10→20은 무예산 recall만 오르고
  recall@300은 포화(0.123→0.122). → **에이전트 관점 추천: top_k 기본 5는
  유지하되, 탐색형 질의에는 10을 권장하는 문구를 도구 설명에 추가할 가치**
  (SWE-Explore의 "누락이 잡음보다 치명적" 발견과 일치).
- **RRF k 불변은 정상**: lexical-only에서는 RRF 병합이 일어나지 않아 k가
  관여하지 않는다. k 스윕은 hybrid 런에서만 의미가 있다.

## H1 보류 사유 (기술적 블로커)

hybrid 런은 모델 캐시가 있어 실행 자체는 가능하나, 현재
`SemanticReady`는 **모델 워밍업 완료**를 뜻할 뿐 **임베딩 큐 드레인**을
보장하지 않는다. 방금 부트스트랩한 저장소는 벡터가 거의 비어 있어 측정이
lexical과 사실상 동일하거나 비결정적으로 흔들린다. 공정한 H1은 graphin에
"임베딩 큐 드레인 대기" 신호(예: 큐 깊이 노출 또는 drained 상태)를 추가한
뒤 재실행해야 한다. → Phase 7c 후속 작업 후보 #1.
