## 실행 이력 — 중단과 병합

초기 4회 실행이 호스트 OOM으로 중단됐다. 원인은 graphin의 semantic 엔진이
종료 시 ORT 세션을 해제하지 않은 것(세션당 수백 MB)과, 하니스가 스윕 config
마다 재부트스트랩해 그 누수를 27배로 증폭한 것이다 — 태스크당 약 1GB씩
누적되어 8GB VM 캡에 6~8태스크째 도달했다. `d78140b`이 양쪽을 수정했다.

병합의 정당성은 두 가지로 확인했다:
- 수정 전후 동일 인스턴스(`pydata__xarray-2905`)의 27개 config 제출이 **바이트 동일**.
- 하니스 유닛 테스트가 "세션 리플레이 == config별 재부트스트랩" 동등성을 강제.

부분 런은 `remaining.py`(모든 config에 존재하지 않는 인스턴스만 재실행) →
`merge_submissions.py`(instance_id keep-first) 절차로 합쳐 40/40 × 27 config를
완성했다.

## 측정 캐비앗 — 임베딩 큐 드랍

5개 인스턴스에서 백프레셔 드랍이 발생했다(django 3개는 15.3k~15.8k개로
큐 상한 16,384에 육박 — 벡터 인덱스 절반 이하). 대형 저장소 초기 인덱싱에서
구조적으로 발생하는 현상이며, `findings.md`가 드랍 포함/제외 양쪽 수치를
모두 제시한다.

## 결과 요약

- **H1 불충분 — 판정 보류**(지지 아님). recall 평균 +1.70%p이나 부호검정
  p ≥ 0.24로 유의하지 않고, k5 평균의 절반이 단일 이상치(+80.3%p)에서
  나오며, ndcg@300은 오히려 −0.84%p(드랍 제외 시 −4.9%p까지) 악화된다.
- 시맨틱 이득은 예산이 좁을수록 크다: k5 +3.53%p → k20 +0.64%p.
- H3는 하이브리드에서 더 강해진다: recall@300 0.140 vs grep 0.026 (5.4×).
- **권고: 하이브리드를 기본으로 승격하지 않는다.** 재검증은 인스턴스 400+
  및 드랍 0 조건에서.
