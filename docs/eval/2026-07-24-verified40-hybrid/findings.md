# H1 하이브리드 검증 결과 해석 (2026-07-24, Verified 40, semantic)

`report.md`(스윕 표·판정)와 `h1_detail.md`(인스턴스 단위 통계)의 해석.
채점은 SWE-Explore-Bench 공식 `eval.py`.

## H1 판정: **불충분 — 보류** (지지 아님)

집계 평균만 보면 hybrid가 lexical보다 recall +1.70%p로 우세해 보이지만,
인스턴스 단위로 열어보면 그 우세가 잡음과 구분되지 않는다.

| 근거 | 내용 |
|---|---|
| 부호검정 | k5 recall 19승/14패/7무 → p=0.487. k10 p=0.345, k20 p=1.000. 어느 config도 유의하지 않다 |
| 이상치 지배 | k5 평균 +3.53%p 중 절반 이상이 단 하나의 인스턴스(+80.3%p)에서 나온다. 그 인스턴스를 포함한 드랍 5개를 빼면 +1.72%p로 반토막 |
| 랭킹 품질 역행 | ndcg@300은 k10 −2.84%p, k20 −2.43%p로 **악화**. 드랍 인스턴스를 빼면 −5.17%p / −4.85%p로 더 나빠진다 |

즉 시맨틱은 가끔 결정적으로 맞히지만(한 인스턴스 +80%p) 평균적으로는
**순서를 흐트러뜨린다**. 40개 인스턴스로는 "recall이 조금 오른다"와
"아무 차이 없다"를 가를 수 없다.

### top_k 상호작용 (실질 발견)

시맨틱의 recall 이득은 예산이 좁을수록 크다: k5 +3.53%p → k10 +1.02%p →
k20 +0.64%p. 후보를 많이 볼 수 있으면 BM25만으로도 충분히 닿는다는 뜻으로,
"넓게 보는 것"과 "의미로 찾는 것"이 상당 부분 대체재임을 시사한다.

## 임베딩 큐 백프레셔 (측정 캐비앗)

5개 인스턴스에서 드랍 발생. django 3개는 15,355~15,769개로 큐 상한
(16,384)에 육박 — 벡터 인덱스가 사실상 절반 이하만 채워진 채 측정됐다.
`Enqueue`가 non-blocking drop 정책이라 대형 저장소의 초기 인덱싱에서
구조적으로 발생한다. 다만 40개 전부에서 hybrid 제출이 lexical과 달랐으므로
부분 인덱스도 기여는 했다.

→ 후속 후보: 초기 스캔 경로에 한해 Enqueue를 블로킹으로 하거나 큐 상한을
동적으로(노드 수 비례) 잡는다. 현재 상한은 대형 저장소에서 조용히 절반을
버린다.

## H2·H3 재확인 (하이브리드 런에서도 동일)

- H2: min_confidence는 여전히 no-op (confidence 최저 티어 0.8 < 스윕 축).
- H3: PASS 유지 — 300라인 예산 recall 0.107 vs grep 0.026, 라인 3.1%.
  하이브리드에서는 recall@300이 0.140까지 올라 격차가 5.4×로 벌어진다.

## 권고

1. **하이브리드를 기본으로 승격하지 않는다.** 인덱싱 비용(태스크당 수십 초
   → 수 분)과 메모리를 요구하는데 근거가 유의하지 않고 랭킹은 나빠진다.
   현 상태 유지(시맨틱은 옵션, lexical이 기본 경로)가 데이터에 부합한다.
2. **재검증 조건**: 인스턴스 400+로 확대하고 임베딩 드랍을 0으로 만든 뒤
   재실행. 그때 ndcg 역행이 사라지는지가 핵심 관전 포인트.
3. min_confidence 스윕 축을 {0.75, 0.85, 0.95}로 교체(H2를 의미 있게).
